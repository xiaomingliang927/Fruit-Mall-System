## 一、本轮（E2E 测试）新发现并修复

### 🔴 高·跨端同步价格单位错位（已修复 + 验证通过）

- **问题**：后端 `CartVO.price` / `subtotal` 是**「分」**（`sku.getPrice()`，如香蕉 `590` 表示 ¥5.90）；前端本地购物车快照的 `price` 是**「元」**（`data.js` 里 `p.minPrice / 100`）。`syncFromServer` 给「本地没有、从服务端补进来」的项直接写 `price: it.price`，于是同步进来的商品单价与合计被放大 **100 倍**。
- **复现/证据**（测试 S5，修复前）：
  - 香蕉单价显示 `¥590`（应为 `¥5.90`）；火龙果 `¥790`（应为 `¥7.90`）。
  - 购物车合计 `¥3150.00`（应为 `¥31.50`）。
  - 影响：登录后，凡服务端购物车有、本地没有的商品，价格全部错乱；下单金额若沿用本地合计会严重错误。
- **修复**：`miniapp/src/utils/cart.js` 的 `syncFromServer` 改为 `price: (it.price || 0) / 100`，并补注释说明单位。
- **验证**：修复后重跑全量 29 条断言全部 PASS（S5 由 FAIL 转 PASS），确认单价 `5.9`、合计 `31.50`。
- **遗留风险**：仅修了购物车同步这一处。前端「元」、后端「分」的混用在**订单/优惠券/详情页价格传递**中是否还有类似错位，尚未全量审计（见下方「中」第 2 条）。

### 🔴 高·购物车数量减到 0 时未持久化删除（已修复 + 验证通过）

- **问题**：`miniapp/src/utils/cart.js` 的 `decQty` 在 `qty <= 0` 分支执行了 `delete cart[id]`，但**漏了 `saveCart(cart)`**。内存里的购物车对象删了，本地存储还在；组件层面商品会短暂消失，但 `updateCartBadge()` 读存储得到的数量仍是 1，TabBar 红点去不掉，重新进入购物车页面商品又出现。
- **复现/证据**：
  - 用户截图：购物车剩「商品 ×1」，点减号后底部购物车 Tab 红点 `1` 仍在。
  - E2E 原 29 条断言只读组件状态，没查 storage，因此漏了；新增 S1/S2「递减至 0 后 storage 清空」断言后复现（修复前 FAIL）。
- **修复**：在 `decQty` 的 `qty <= 0` 分支 `delete cart[id]` 后补 `saveCart(cart)`；同步 `miniapp-hbx/utils/cart.js`。
- **验证**：重跑 31 条断言全部 PASS（新增 2 条 storage 清空断言）。

### 🔴 高·订单号并发碰撞撞唯一索引（压测第一期发现，已修复 + 验证通过）

- **问题**：`OrderService.generateOrderNo()` 用 `"FM" + 秒级时间戳 + 4 位随机数`（每秒仅 10000 种组合）。20 并发各下 10 单（200 单/秒）时按生日悖论必然碰撞（期望 ≈ 200²/(2×10000) ≈ 2 次），实测撞了 2~3 个 `order_no`，命中 `uk_order_no` 唯一索引抛 `DuplicateKeyException`，**下单直接失败**且无重试兜底。
- **复现/证据**：`OrderCreateLoadTest` 压测日志 `Unique index or primary key violation: "public.uk_order_no ... VALUES (/* 62 */ 'FM2608311658483067')"`；防超卖用例 100 并发中也偶发同款异常。
- **修复**：去掉随机数，改为**进程内原子自增 6 位序号**（`AtomicInteger`，容量 100 万单/秒，同 JVM 同秒必不重复）；DB 唯一索引保留作最终兜底。
- **验证**：修复后 3 个压测用例全 PASS（购物车 1600 操作 / 下单吞吐 200 单 / 100 并发抢 50 库存）；全量后端测试无回归。
- **遗留风险**：多实例部署时各实例序号独立，同秒跨实例仍可能碰撞——当前单实例无影响；上多实例需加实例标识或改雪花号（已在 `压测方案.md` 记录）。

## 二、仍待优化（按优先级）

### 🔴 高

#### 1. 退出登录 / 清缓存文案过度承诺（✅ 已修复）
- **问题**：`settings.vue` 退出确认文案「退出后购物车会清空本地暂存，**重新登录还能找回**」，清缓存文案「只清**商品图**和购物车暂存」「会清掉购物车暂存和**图片缓存**」——`clearLocalMirror()` 实际只清购物车/勾选两个 storage 键，**从未清理图片缓存**；且「能找回」仅对已同步服务器的商品成立，本地暂存未同步的商品退出即丢。
- **修复**：三处文案改为如实描述——清缓存说明改为「只清购物车等本地暂存，不会退出登录」；清缓存弹窗与退出弹窗均明确「已同步到服务器的商品不受影响；只在本地暂存、还没同步的商品会被清掉」，并删去图片缓存的不实表述。`mine.vue` 退出弹窗本就中性，无需改。
- **验证**：同步 miniapp-hbx；E2E S6 设置页锚点更新后全量 31 条断言 PASS。

#### 2. 价格单位未全局收敛（分/元混用，仅修了一处）
- **问题**：本项目价格后端用「分」、前端本地用「元」，缺少统一收口。本轮只在购物车同步处补了 `/100`，但订单、优惠券、商品详情、会员统计等处的金额传递尚未系统审计。
- **证据**：后端 `CartVO`/`OrderListVO`/`MemberStat` 等多处用「分」；前端 `data.js` 用 `minPrice/100`；`getCartTotal()`/`totalPrice` 直接 `price*qty` 假定「元」。任何一处忘了换算就会 100× 或 100÷ 错误。
- **建议**：
  - 抽一个 `money.js`：`centsToYuan(c)` / `yuanToCents(y)`，前端所有金额出入都过这一层；
  - 接口层（VO/文档）显式标注单位（如 `priceCents`）；
  - 补一个纯函数单测，防前后端再次错位。

### 🟡 中

#### 3. 购物车空态推荐是静态前端列表
- **问题**：`cart.vue` 推荐位 `recommends = PRODUCTS.slice(0, 4)`，`PRODUCTS` 是前端写死的 10 条静态数据，非服务端实时。
- **影响**：推荐与库存、下架、个性化完全脱节；服务端下架/无货的商品仍可能被推荐。
- **建议**：接后端「热销/猜你喜欢」接口（如新增 `/api/v1/products/hot`），按 `stock>0 && status=1` 过滤。

#### 4. 商品图 404（静态资源 / 域名路径）
- **问题**：E2E 测试中购物车/详情的商品图 `src` 指向 `/images/products/*.jpg`，本地 H5 下 404。
- **影响**：H5 与真机/线上图片域名、路径配置可能不一致（本地 `/images/...` vs 线上 CDN）。
- **建议**：核实图片 base URL 配置（H5 用绝对/可配置域名），保证三端图片可访问。

#### 5. 结算功能未接通后端下单
- **问题**：`cart.vue` 去结算仅 `uni.showToast('结算功能开发中')`；后端下单接口已存在（`OrderService.createOrder`）。
- **影响**：购物车到订单的主流程断在最后一环，无法端到端验证下单/库存扣减/支付。
- **建议**：补 `checkout()` → 调创建订单接口 → 跳订单确认/支付页；同时把 E2E 增加「下单流程」场景。

#### 6. 收货地址无修改接口（仅增删）
- **问题**：`address.vue` 只能增/删，因后端 `UserController` 无 update 地址接口。
- **影响**：用户改地址需「先删后加」，体验差；与网站端行为一致但属历史取舍。
- **建议**：后端加 `PUT /api/v1/users/me/addresses/{id}`；前端加编辑态。

### 🟢 低 / 产品向

#### 7. 会员开通无线上闭环
- **问题**：`vip.vue` 权益展示完整，但开卡由「客服人工」完成（见页内文案），C 端无购买/支付开卡链路。
- **说明**：属业务设计，非 bug；可作为后续产品优化（线上自助开卡 + 支付）。

#### 8. 系统消息空态引导弱
- **问题**：消息中心仅订单/优惠券有数据，系统消息后端无表，前端空态仅留白。
- **建议**：空态增加明确引导文案（如「暂无系统通知」），避免用户以为加载失败。

#### 9. 真机/微信开发者工具图标验收缺口
- **问题**：H5 模式无法验证微信 `<image>` 对本地 SVG 的支持（已用 PNG 栅格化规避真机空白）。
- **建议**：在微信开发者工具/真机单独验收图标（PNG 已就绪，需确认 hbx 构建产物含最新 PNG）。
