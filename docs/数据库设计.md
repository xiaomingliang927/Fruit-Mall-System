# 数据库设计

> 水果商城 · MySQL 8（utf8mb4）｜ 金额单位一律为「分」（INT）｜ 版本化迁移：`backend/src/main/resources/db/migration/`
>
> 现状：V1~V8 已发布。本文档与迁移脚本一一对应，**改表必须新增迁移脚本，禁止修改已发布迁移**。

## 1. 设计规范

| 规范 | 说明 |
|------|------|
| 命名 | 表/字段全小写下划线；表名单数；关联表 `a_b` |
| 金额 | 一律 INT 存「分」，展示层 ÷100，杜绝浮点误差 |
| 主键 | BIGINT AUTO_INCREMENT |
| 时间 | DATETIME；`created_at/updated_at` 由应用层自动填充 |
| 快照 | 订单/评价等冗余商品名、图片、价格快照，历史不受商品改动影响 |
| 删除 | 业务数据不做物理删除（状态位控制）；引用类数据物理删除 |
| 字符集 | utf8mb4；JSON 类内容存 TEXT（兼容 H2 测试库） |
| 迁移 | Flyway；老库接入用 baseline（当前 baseline-version=2） |

## 2. 实体关系总览

```
user 1──n user_address
user 1──n ┌ cart_item（用户×SKU 唯一）
          ├ favorite（用户×商品 唯一）
          ├ user_coupon n──1 coupon
          ├ review 1──1 order_item
          └ refund n──1 order(按 order_no)
order 1──n order_item n──1 product 1──n product_sku
order 1──n payment（支付流水，幂等按回调去重）
product n──1 category（parent_id 支持多级）
admin_user n──n role n──n permission
admin_user 1──n operation_log
```

## 4. 核心表字段说明

### 4.1 `order`（订单主表）
| 字段 | 类型 | 说明 |
|------|------|------|
| order_no | VARCHAR(32) UK | FM+yyMMddHHmmss+4位随机 |
| status | TINYINT | 10待支付 20待发货 30待收货 40已完成 50已取消 60售后中 70已退款 |
| total_amount / pay_amount / freight | INT | 商品总额 / 实付 / 运费（分） |
| address_snapshot | TEXT | 下单时地址 JSON 快照 |
| delivery_type / tracking_no | | 1快递 2同城 3自提 / 运单号 |
| paid_at / shipped_at / completed_at | DATETIME | 状态时间线 |

状态机：`待支付 →(支付回调,幂等) 待发货 →(发货) 待收货 →(确认/7天) 已完成`；逆向：未支付取消（回库存）、已支付走 `refund` 售后单。

### 4.2 `coupon` + `user_coupon`（优惠券两表模型）
- `coupon` 是营销配置（模板）：类型（满减/折扣/无门槛）、门槛、总量、每人限领、可领时间窗。
- `user_coupon` 是用户的券实例：领取时写一行并 `issued_count+1`（并发用乐观扣减），下单核销置 `status=1` 并记 `order_no`，过期由定时任务或查询时惰性置 `2`。
- 金额计算：满减 = `pay_amount - discount_amount`（不低于 0）；折扣 = `pay_amount × percent/10`。

### 4.3 `review`（评价）
- 以 `order_item_id` 唯一约束保证「一明细一评」；
- `product_id` 冗余使商品详情页查询无需联表；`status` 支持先发后审；
- 商家回复 `admin_reply` 直接内联（不拆表）。

### 4.4 `refund`（售后）
- 独立售后单（不直接改订单状态字段），审核通过后由代码联动 `order.status = 60/70`；
- 坏果包赔走 `type=1 仅退款`，金额 ≤ 阈值可自动秒审。

### 4.5 `seckill_activity`（秒杀）
- 库存字段 `available_stock` 独立于 SKU 库存（活动结束后回拨）；
- 上线后配合 Redis 预扣（DECR+Lua）防超卖，DB 只做兜底扣减。

### 4.6 RBAC 四表
- `permission.code` 与前端菜单 `perm` 编码对齐（如 `member:list`、`order:ship`）；
- 管理员登录后返回角色→权限码集合，后端按编码拦截接口，前端按编码渲染菜单。

## 5. 索引设计原则

- 唯一业务键必须唯一索引：手机号、openid、订单号、售后单号、`review.order_item_id`、`cart(user,sku)`
- 查询路径覆盖：`order(user_id)`、`order(status)`、`review(product_id,status)`、`user_coupon(user_id,status)`
- 低区分度字段（如 status）不单独建索引，走组合索引前缀
