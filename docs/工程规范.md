# 工程规范（企业级基线）

## Git 分支模型

```
main        生产分支，只接受 MR/PR 合入，保持随时可发布
dev         集成分支，feature 分支的合入目标
feature/*   功能分支，从 dev 拉出（如 feature/order-refund）
fix/*       缺陷修复分支
```

- `main` 与 `dev` 上禁止直接 push（团队协作时在平台设置保护）；
- 每个 feature/fix 分支生命周期 ≤ 1 周，合入前必须：CI 绿 + 至少 1 人 Review；
- 发版时从 `dev` 切 `release/x.y.z`，验证后合回 `main` 并打 tag（`v主.次.修订`）。

## 提交信息（Conventional Commits）

```
<类型>: <一句话说明>

类型取值：
  feat     新功能
  fix      缺陷修复
  refactor 重构（不改行为）
  test     测试补充/修正
  build    构建/依赖/环境
  ci       持续集成
  docs     文档
  chore    杂项
```

示例：`feat: 售后退款审核流程`、`fix: 支付回调重复落流水`、`test: 补充秒杀库存并发测试`

## 代码规约基线

- 后端：阿里巴巴 Java 开发手册；金额一律 `int`（分）；对外接口统一 `ApiResponse`；
- 异常：业务异常抛 `BizException`，禁止吞异常返回 null；
- SQL：表结构变更必须走 Flyway 新增迁移脚本（`V<版本>__描述.sql`），**禁止修改已发布的迁移**；
- 前端：组件式开发，接口调用统一走 `src/api.js` 封装，不散落请求。

## 小程序避坑清单（踩过的坑，勿重犯）

微信小程序运行在 JSCore 里，既不是浏览器也不是完整 Node，以下四条是本项目实际踩坑后沉淀的硬约束：

1. **`data()` 里禁止出现裸方法名**。写 `{ tap: goFavorite }` 会抛 `ReferenceError: goFavorite is not defined`——方法只挂在实例上（`this.goFavorite`），不在 `data()` 的词法作用域里。一旦抛错，**整个组件的 data 全部为空，页面只剩静态文字**，表现为"莫名白屏"，极难定位。正确做法：`data` 里存 action 字符串，配一张 `xxxRoutes` 映射表，模板统一走 `onXxxTap(item)` 分发。
2. **没有浏览器全局对象**。`URLSearchParams`、`Object.fromEntries`、`document`、`window` 一律不存在。拼查询串用数组 `['page=1','size=20'].join('&')`；构造字典用普通对象 + `forEach`。
3. **`<image>` 不渲染本地 SVG**。开发者工具里能看见（内核是 Chromium），真机/预览一片空白。图标必须转 PNG（本项目用 `@resvg/resvg-js` 输出 96px），SVG 源文件可保留备查。
4. **`miniapp/` 与 `miniapp-hbx/` 必须同步**。前者是 CLI 工程（源码在 `src/`），后者是 HBuilderX 工程（**没有 `src/` 这一层**）。相对导入 `../../api` 在两边都成立，所以文件内容可以逐字相同；每次改完用 `diff -q` 校验，漏同步会导致"某个工具里是好的、另一个里是坏的"。

## 环境与密钥

| 环境变量 | 用途 |
|---------|------|
| `FRUIT_DB_HOST/PORT/NAME/USER/PASSWORD` | 数据库连接 |
| `FRUIT_JWT_SECRET` | JWT 签名密钥（≥32 字符，定期轮换） |
| `FRUIT_WX_APPID/FRUIT_WX_SECRET` | 微信小程序 |

- 任何密钥**不得**提交进仓库；本地用 `.env`（docker compose）或 IDE 运行配置注入；
- 生产以 `--spring.profiles.active=prod` 启动，prod profile 无默认值、缺失即失败。

## 质量门禁（当前）

- `mvn test` 全绿（核心链路：下单锁库存 / 支付幂等 / 取消回补 / 防超卖 / 登录）；
- 三端 CI 构建通过（web / admin-web / 小程序 mp-weixin）。
