# 工程规范（企业级基线）

## Git 分支模型

```
main        生产分支，只接受 MR/PR 合入，保持随时可发布
dev         集成分支，feature 分支的合入目标
feature/*   功能分支，从 dev 拉出（如 feature/order-refund）
fix/*       缺陷修复分支
```

- `main` 与 `dev` 上禁止直接 push（团队协作时在平台设置保护）；
- 每个 feature/fix 分支生命周期 ≤ 1 周，合入前必须：CI 绿 + 至少 1 人 Review；
- 发版时从 `dev` 切 `release/x.y.z`，验证后合回 `main` 并打 tag（`v主.次.修订`）。

## 提交信息（Conventional Commits）

```
<类型>: <一句话说明>

类型取值：
  feat     新功能
  fix      缺陷修复
  refactor 重构（不改行为）
  test     测试补充/修正
  build    构建/依赖/环境
  ci       持续集成
  docs     文档
  chore    杂项
```

示例：`feat: 售后退款审核流程`、`fix: 支付回调重复落流水`、`test: 补充秒杀库存并发测试`

## 代码规约基线

- 后端：阿里巴巴 Java 开发手册；金额一律 `int`（分）；对外接口统一 `ApiResponse`；
- 异常：业务异常抛 `BizException`，禁止吞异常返回 null；
- SQL：表结构变更必须走 Flyway 新增迁移脚本（`V<版本>__描述.sql`），**禁止修改已发布的迁移**；
- 前端：组件式开发，接口调用统一走 `src/api.js` 封装，不散落请求。

## 环境与密钥

| 环境变量 | 用途 |
|---------|------|
| `FRUIT_DB_HOST/PORT/NAME/USER/PASSWORD` | 数据库连接 |
| `FRUIT_JWT_SECRET` | JWT 签名密钥（≥32 字符，定期轮换） |
| `FRUIT_WX_APPID/FRUIT_WX_SECRET` | 微信小程序 |

- 任何密钥**不得**提交进仓库；本地用 `.env`（docker compose）或 IDE 运行配置注入；
- 生产以 `--spring.profiles.active=prod` 启动，prod profile 无默认值、缺失即失败。

## 质量门禁（当前）

- `mvn test` 全绿（核心链路：下单锁库存 / 支付幂等 / 取消回补 / 防超卖 / 登录）；
- 三端 CI 构建通过（web / admin-web / 小程序 mp-weixin）。
