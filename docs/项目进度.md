### 2. 交易闭环（M1）

登录（短信 + 微信自动登录跨设备同账号）→ 商品（10 款鲜果集水果 + 真实摄影图）→ 购物车（**三端同步**）→ 下单（乐观锁防超卖）→ 支付（M1 模拟）→ 发货（运单号）→ 确认收货 → 评价。

### 3. M2 营销与服务（全部完成）

- **售后退款（坏果包赔）**：申请 → ≤50 元自动秒审 / 超额人工审核 → 退款回库存 / 驳回恢复订单状态；用户可撤销
- **优惠券**：后台建券（满减/折扣/无门槛，限领/总量/时间窗）→ 领券中心（网站+小程序）→ 结算页选券抵扣 → 取消退券；乐观扣减防超发
- **评价系统**：完成单评价（星级/内容/匿名，明细粒度防重复）→ 商品详情评分聚合（均分+条数）→ 后台回复 / 显示隐藏
- **图片上传闭环**：后端上传接口（jpg/png/webp ≤5MB，日期分目录）+ 磁盘静态映射 `/uploads/**`；网站售后弹层选图即传（≤3 张、可删可重选）、小程序 `chooseImage` + `uploadFile`（相册/拍照/压缩）、管理后台售后审核页凭证缩略图 + 大图预览

- **RBAC 权限落地**：权限点 26 个（与菜单 perm、接口映射三者对齐）+ 内置角色（超级管理员/运营专员/只读观察员）；`AdminInterceptor` 按 `PermissionRegistry` 逐点校验（未登记接口默认放行、超管跳过）；后台「系统设置 → 角色权限」支持角色增删改与账号授权；登录后返回权限点，侧边菜单按权限显隐

### 6. 安全与越权加固（本轮新增，已落地 + 8 个测试守护）

原交易链路功能完整，但上线前补了 5 处安全短板，均纯代码、零外部依赖：

- **短信验证码风控**：新增 `SmsCodeService`，生成 6 位码 + 内存存储（5 分钟过期）+ 同号 60s 重发限制 + 每小时上限 10 次 + 试错 5 次作废；`loginBySms` 改为走真实校验，新增 `/api/v1/auth/sms-code` 发码端点。开发模式保留万能码 `123456` 不破坏联调，接真实短信网关后关 `FRUIT_SMS_DEV_MODE=false` 即可。
- **C 端/管理端 token 隔离**：`JwtInterceptor` 现在拒绝带 `role=admin` 的 token，管理端 token 再也打不进 C 端接口（管理端此前已拒绝 C 端 token，双向闭环）。
- **XSS 清洗**：新增 `HtmlSanitizer`，存储前剥离评价内容、订单备注、收货地址文本中的 `<script>`/事件属性等；前端 Vue 自动转义叠加双重防护。
- **CORS 收紧**：去掉 `*` + `allowCredentials` 危险组合，改为按 `FRUIT_CORS_ORIGINS` 显式白名单（默认仅本地三端）。
- **JWT 续期**：新增 `/api/v1/auth/refresh`，用未过期旧 token 换发新 token（向后兼容，前端可忽略）。
- **归属校验复核**：审计确认订单/退款/评价/购物车/地址的 owner 校验本就正确，并新增越权测试证明「用户 B 读不到用户 A 的订单」。
- **防超卖压测**：新增并发测试，100 线程抢购库存 50 的 SKU，断言恰好售罄、绝不超发（`decreaseStock` 的 `WHERE stock>=?` 原子条件更新兜底）。

## 三-甲、被阻塞项与接入握手清单

**真实微信支付（路线 #2）当前完全阻塞在用户侧，非开发侧问题**：微信支付必须先用「营业执照」申请商户号，没有商户号就没有 `mchid` 与 APIv3 密钥，开发方无法任何接入。一旦用户具备资质，按以下清单交给我即可改为真实支付（其余代码我来做）：

1. 营业执照（个体工商户/企业均可，水果零售需对应经营范围）
2. 微信支付商户号 `mchid`（pay.weixin.qq.com 申请）
3. APIv3 密钥（商户平台 → API 安全 → 设置 APIv3 密钥）
4. 商户 API 证书序列号 + 证书/私钥（APIv3 回调验签与退款必需）
5. 小程序/公众号 AppID（与商户号同主体，已配置 `FRUIT_WX_APPID`）

届时改动范围：`application.yml` 注入上述密钥（走环境变量，不入库）、`PayController` 由 mock 改为 JSAPI 下单 + 回调通知 + 退款，前端支付按钮无需改动。
